# 1С 8.5 → FastAPI → PostgreSQL: MVP

## 1. Результат анализа backend

API менять не требуется. `src/integration/router.py` подключен через `src/routers.py`.
Маршрут: `POST http://127.0.0.1:8000/integration/purchases` при прямом запуске uvicorn.
`root_path=/api` не добавляет префикс к прямому маршруту.

* Авторизация: `X-Integration-Key`, значение `INTEGRATION_API_KEY` из `backend/.env`.
  JWT и вход библиотекаря не нужны. Сравнение ключа — `secrets.compare_digest`.
* Нет/неверный ключ: 401; ключ не настроен на сервере: 503.
* JSON: `document_id` (1–200 символов), `books` (1–100 строк).
  Название 1–500 символов, автор и издатель 1–300, пробелы по краям удаляются.
  Год 1–9999; количество строго целое 1–1000; сумма до 5000. Лишние поля запрещены.
  Валидация возвращает 422. Поле `publication_year` в текущей Pydantic-схеме не strict,
  однако 1С передает его числом, без строкового форматирования.
* `service.py` объединяет одинаковые издания, сортирует строки, считает SHA-256.
  Тот же ID и те же данные → 200, `already_imported=true`, без новых экземпляров.
  Тот же ID с другими данными → 409. Порядок строк для backend не важен.
* `repository.py`: совпадение по названию, автору, году и издателю; точный регистр
  и внутренние пробелы. Новое издание → `books`; каждый экземпляр → `book_copies`.
  Результат → `purchase_imports` с уникальным `document_id`.
* Общая транзакция, commit после всех записей, rollback при исключении.
  PostgreSQL advisory lock сериализует импорты. Другие операции каталога этим
  lock не защищаются; это не глобальное ограничение уникальности изданий.

Ответ:

```json
{"success":true,"data":{"document_id":"1c:UUID","already_imported":false,
"created_books":1,"created_copies":5,"books":[{"book_id":"UUID","quantity":5}]}}
```

Счётчики при повторе относятся к первоначальной загрузке. Исправление и отмена
импорта не реализованы. Новая копия документа с другим UUID добавит экземпляры.

## 2. Проверка учебной версии на macOS

На данном Mac обнаружена `/Applications/1cv8t.localized/8.5.1.1150`.
Официальная [страница именно учебной 8.5.1.1150 для macOS](https://online.1c.ru/catalog/free/36179925/)
перечисляет ограничения: файловый режим (клиент-сервер запрещен), один сеанс,
лимиты данных, отсутствие COM. Ограничение исходящего HTTP там не указано.
Это основание выбрать встроенный HTTP, но не доказательство выполнения нашего
кода в конкретной установленной базе.

Официальные материалы: [HTTPСоединение и обработка ошибок](https://its.1c.ru/db/content/metod8dev/src/developers/platform/demo/i8105574.htm),
[встроенная сериализация JSON](https://wonderland.v8.1c.ru/blog/sredstva-raboty-s-json/).
Не используются COM, curl из 1С, внешние компоненты и публикация самой 1С на веб-сервере.

Обязательная проверка в установленной 1С: кнопка **Проверить HTTP** из этого
комплекта выполняет настоящий POST без ключа и ожидает 401 (или 503 до настройки
backend). Данные не импортируются. Если проверка не прошла, переходить к
демонстрации поступления нельзя. Ошибка компиляции означает, что надо проверить
синтакс-помощник установленной версии и контекст модуля; ошибка соединения —
запуск backend, адрес, ограничения доступа к сети. Для MVP используйте файловую
базу и настольный клиент на том же Mac, что и FastAPI.

Учебная версия подходит для демонстрации, а не реального учета предприятия.
PostgreSQL является базой FastAPI; саму учебную 1С к PostgreSQL не подключаем.

## 3. Объекты конфигурации

Создавайте в пустой учебной конфигурации. Если библиотечная конфигурация уже есть,
сначала сопоставьте существующие объекты: не заменяйте конфигурацию целиком.
Имена ниже — технические, без пробелов; синонимы можно задать с пробелами.

| Объект | Имя | Тип / параметры |
|---|---|---|
| Справочник | `Книги` | Неиерархический, стандартное Наименование длина 500 |
| Реквизит книги | `Автор` | Строка 300 |
| Реквизит книги | `ГодИздания` | Число 4, точность 0, неотрицательное |
| Реквизит книги | `Издательство` | Строка 300 |
| Документ | `ПоступлениеКниг` | Стандартные Номер и Дата; проведение запретить |
| Табличная часть документа | `Книги` | Строки поступления |
| Реквизит табличной части | `Книга` | СправочникСсылка.Книги |
| Реквизит табличной части | `Количество` | Число 4, точность 0, неотрицательное |
| Реквизит документа | `JSONОтправки` | Строка неограниченной длины (длина 0) |
| Реквизит документа | `Отправлен` | Булево, начальное значение Ложь |
| Константа | `КлючИнтеграции` | Строка 200 |
| Общий модуль | `ОбменБиблиотека` | Сервер Да; остальные флаги Нет |

`JSONОтправки` хранит снимок данных перед первой отправкой. Он нужен для
безопасного повтора после таймаута. Не выводите его как редактируемое поле.
`Отправлен` — только локальная отметка; истина об импорте хранится на backend.
Не очищайте JSON вручную после сетевой ошибки. Строки и карточки книг после
первой попытки должны оставаться прежними: код отклонит повтор с изменениями,
включая перестановку строк (это консервативная локальная проверка снимка).

## 4. Куда вставить код в Конфигураторе macOS

1. Откройте стартовое окно учебной 1С. **Добавить → Создание новой информационной
   базы → без конфигурации**, выберите файловый каталог. Откройте **Конфигуратор**.
   При наличии своей базы сначала сделайте резервную копию через
   **Администрирование → Выгрузить информационную базу**.
2. **Конфигурация → Открыть конфигурацию**. В корневых свойствах используйте
   управляемое приложение; режим совместимости — актуальная версия либо
   «Не использовать». Названия пунктов могут немного отличаться по интерфейсу.
3. Через правую кнопку / Control-click на **Справочники → Добавить** создайте
   `Книги`, задайте длину стандартного Наименования 500 и перечисленные реквизиты.
4. **Документы → Добавить**: `ПоступлениеКниг`, проведение — запретить.
   Добавьте реквизиты `JSONОтправки`, `Отправлен`, табличную часть `Книги`
   с двумя колонками. Установите проверку заполнения для книги и количества;
   диапазоны дополнительно проверяет код перед отправкой.
5. **Общие → Константы**: создайте `КлючИнтеграции`. Создайте общую форму
   констант через конструктор, включив эту константу. Вынесите форму в интерфейс
   подсистемы `Библиотека`. Для поля ключа включите режим пароля, если он доступен.
   Это маскировка на экране, не шифрование хранения в учебной базе.
6. Создайте подсистему `Библиотека`, включите в её состав справочник и документ,
   настройте команды открытия списков. Это позволит создать книгу и поступление
   из пользовательского интерфейса без обращения к коду.
7. **Общие → Общие модули → Добавить**: `ОбменБиблиотека`.
   В свойствах оставьте **Сервер = Да**, **Глобальный = Нет**,
   **Вызов сервера = Нет**, клиентские флаги = Нет, привилегированный = Нет.
   Откройте модуль и вставьте целиком [ОбменБиблиотека.bsl](ОбменБиблиотека.bsl).
   Серверный контекст в файловой базе исполняется локально: отдельного сервера 1С нет.
8. У документа откройте **Формы → Добавить → Форма документа**, назначьте основной.
   Включите Номер, Дата и таблицу Книги с обеими колонками.
   `Отправлен` можно вывести с «Только просмотр». `JSONОтправки` не выводите.
9. В редакторе формы откройте вкладку **Модуль** и вставьте
   [ФормаПоступленияКниг.bsl](ФормаПоступленияКниг.bsl).
   Если форма уже содержит код, добавьте процедуры, сохранив существующие;
   одинаковые имена не дублируйте.
10. На вкладке **Команды** формы добавьте `ПроверитьHTTP` и
    `ОтправитьВБиблиотеку`. Для каждой укажите действие — одноимённую клиентскую
    процедуру из модуля. Перетащите команды на командную панель формы.
    Синонимы: «Проверить HTTP» и «Отправить в библиотеку».
11. Выполните **Конфигурация → Проверка конфигурации** (сервер и используемый
    клиент), затем **Конфигурация → Обновить конфигурацию базы данных**.
    Используйте меню, чтобы не зависеть от сочетаний клавиш Mac/Fn.
12. Запустите **Отладка → Начать отладку** / 1С:Предприятие.
    В форме констант вставьте ключ из `backend/.env`, сохраните. Сам `.env`
    в 1С не импортируется. Ключ не должен попадать в BSL, скриншоты или Git.

Файлы BSL — исходники для вставки в модули, а не готовая конфигурация `.cf`.
Создание метаданных в Конфигураторе обязательно.

## 5. Запуск и демонстрация

Из `backend` (окружение здесь — `backend/.venv`, не корневая `.venv`):

```sh
docker compose up -d db
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Если процесс на 8000 уже запущен, остановите его Ctrl+C в его терминале и
запустите снова после изменения `.env`. Перезагрузка исходников не гарантирует
перечитывание `.env`. Не используйте `python -m python`: это причина ошибки
`No module named python`.

1. Откройте новый документ в 1С. Нажмите **Проверить HTTP**. Ожидается сообщение
   «HTTP POST и JSON доступны… 401 … (ожидаемо)». 503 означает необходимость
   настройки ключа в backend, даже если ключ уже введен в константу 1С.
2. В справочнике создайте книгу: Мастер и Маргарита / Михаил Булгаков /
   1967 / Издательство. В табличной части поступления выберите ее, количество 5.
3. Нажмите **Отправить в библиотеку**. Форма сначала запишет документ, затем
   сохранит снимок JSON и отправит его. ID имеет вид `1c:<UUID ссылки>` и не
   зависит от номера. Для нескольких источников понадобится отдельное
   пространство ID; это вне однобазового MVP.
4. Ожидается «Поступление принято… экземпляров: 5». Если такое издание уже есть,
   `created_books=0` — это корректно: добавятся только экземпляры.
5. Нажмите отправку ещё раз: «Документ уже был принят…», без новых экземпляров.
6. Для проверки PostgreSQL скопируйте `document_id` из сохранённого JSON
   (в отладчике Конфигуратора, свойство документа `JSONОтправки`) и выполните:

```sh
.venv/bin/python integration_1c/check_postgres.py --document-id '1c:ВАШ-UUID'
```

Это чтение реальной PostgreSQL из настроек `.env`. Выводит запись импорта,
название книги и количество физических экземпляров. При отсутствии записи
завершается с ошибкой. `total_copies` может быть больше количества в документе,
если были другие поступления. Отдельной таблицы связи «поступление → экземпляр»
в API нет: результат хранит `book_id` и количество, экземпляры — ссылку на книгу.

Для проверки без 1С, с настоящим HTTP и постоянной тестовой записью:

```sh
.venv/bin/python integration_1c/check_postgres.py --send --document-id mvp-http-smoke-001
```

Скрипт проверяет импорт, повтор без увеличения экземпляров, 409, 401 и 422.
Использует отдельное тестовое издательство, чтобы отличать тест от демонстрации
из 1С. Сохраняет 5 экземпляров, не удаляет их после проверки. Повтор с тем же ID
безопасен. Для временного сервера можно указать `--url http://127.0.0.1:8001`.

## 6. Ошибки и границы MVP

* Нет связи/таймаут: результат неизвестен; повторить тот же документ. Backend
  мог успеть сделать commit до потери ответа. Не копировать документ ради повтора.
* 401: сравнить ключ в константе и `.env`; перезапустить backend после настройки.
* 409: остановить отправку, проверить прежний импорт. Не обходить сменой UUID.
* 422: сообщение включает тело ответа с деталями. Исправьте данные до первой
  реальной отправки. Если снимок уже сохранен, сначала выясните результат на
  backend; автоматического сброса снимка намеренно нет.
* 5xx: устранить ошибку сервера, повторить тот же документ.
* 200 с неожиданным JSON: успех в 1С не отмечается; повтор с тем же ID безопасен.
* Не сохранилась локальная отметка после 200: выводится отдельное предупреждение;
  backend уже принял поступление, повтор восстановит отметку без дублирования.

HTTP ограничен localhost для демонстрации. Код выполняется синхронно с таймаутом
30 секунд; форма на это время занята. Проведение, бухгалтерские регистры, списание,
цены, отмена и редактирование принятого поступления не реализованы.
